# Design

The Claude Design handoff for The Gaffer, plus one derived file. Committed under STE-74.

## What wins, and over what

**This folder is authoritative for visual truth only** — colour, type, spacing, radii, shadows,
component anatomy, layout hierarchy, assets.

**`docs/criteria/` is authoritative for behaviour**, without exception. Thresholds, flag rules, what
a control does, what a screen shows when: those come from the criteria files, which are extracted
verbatim from the PRD. `handoff/README.md` contains sections titled *Interactions & behaviour*,
*Model rules* and *Hard constraints*, and they are a useful description of the design's intent —
but where any of them disagrees with a criteria file, **the criteria file is right and the handoff
is stale**. Do not resolve such a conflict by reading both and picking; say so instead.

## The prototype

`handoff/FPL Advisor Prototype.dc.html` is a behaviour *reference*, not a specification, and its
left-hand panel is a demo harness rather than part of the product. Use it to reach states that are
several steps in — first login versus returning, blank and double gameweeks, forced-only filtering,
post-refresh diffs, each failure screen.

It was **corrected at source on 2026-09-03** on the three points where it contradicted the
reconciled requirements: the `forced` flag was being derived from conviction crossing ~90%, two
calls acted on the same player, and two calls brought in the same player. All three are fixed, so
the earlier "known stale on three points" caveat no longer applies.

**Its demo data is specification-by-example.** An agent reading it will infer rules from what it
shows, which is why the forced examples deliberately span both directions — one forced call at 94%
conviction and one at 59% — so that *forced is not confidence* is visible rather than merely
un-contradicted.

**One rule it deliberately does not encode.** Whether a blanking incumbent forces the armband is
open — F4-AC-07 says forced applies to availability 0 only, and a blanking player is fully fit with
no fixture. The prototype follows the criterion as written. Tracked as STE-77.

## Files

| Path | What it is |
| --- | --- |
| `handoff/README.md` | The handoff's own documentation. Authority for token values. |
| `handoff/FPL Advisor Design System.dc.html` | Visual reference — palette, type, controls, widgets, states. |
| `handoff/FPL Advisor Prototype.dc.html` | Behaviour reference and demo harness. |
| `handoff/support.js` | Runtime needed to open the two HTML files. Not part of the design. |
| `handoff/assets/` | The two Gaffer illustrations. Project-owned. No player photographs exist or should be introduced. |
| `TOKENS.md` | Derived — measured WCAG contrast for every text token against every surface. |

## Regenerating

The handoff is exported from Claude Design and copied in whole. It is **not** generated by a script
in this repo, so it does not participate in the `extract-criteria.py --check` drift mechanism that
covers `docs/criteria/`. Re-exporting replaces `handoff/` wholesale; `TOKENS.md` must then be
recomputed, because it is derived from token values that may have moved.
